# Feature V4 probe papers and source-data origins

Research checked 2026-11-07. This is a primary-source design note, not a new detector result. The repository has no root `GLOSSARY.md` or `docs/adr/` at this point. Existing V4 collection uses frozen Qwen2.5-3B-Instruct and saves content-last, content-mean, and assistant-boundary states from one task-conditioned rendering at blocks 6, 18, and 30; its 1,012 label-free rows are not an independent evaluation set ([collection protocol](../FEATURE_V4_COLLECTION.md), [solo review policy](../FEATURE_V4_SOLO_REVIEW_PLAN.md)).

## Methods that bear on the next probe experiment

| Primary work | Mechanism and useful test | Limit for SMAIP |
| --- | --- | --- |
| [TaskTracker, Abdelnabi et al.](https://arxiv.org/html/2406.00799v3) ([authors' code](https://github.com/microsoft/TaskTracker)) | Contrast the final pre-generation hidden state for the authorized task alone with the state after external content; fit a linear probe on the difference, or use metric learning. Test a **task-only versus task-plus-tool-result delta** against V4's raw task boundary on the same examples. | The actual task must vary. Subtracting one constant baseline from every row adds no information to a centered linear probe. Task drift is distinct from whether an unauthorized action occurs. |
| [Agentic IPI exposure probes, Dong et al., v2](https://arxiv.org/html/2608.02657v2) ([authors' code](https://github.com/jianshuod/IPI-exposure-signal)) | Label assistant-facing points by whether the latest tool result exposed an injection; read pre-generation states and fit simple linear probes. Held-out splits vary attacks, agent instructions, and suites. Test V4 boundary against content pooling with grouped, source-held-out selection. | Reported 0.90+ AUROC is not TPR at 1% FPR or an agent-security guarantee. The paper selects its displayed best layer using its held-out-strict AUROC, so that maximum is descriptive, not an independent layer-selection test. Its Qwen3-family layers cannot be copied to Qwen2.5. |
| [InstructDetector, Wen et al.](https://arxiv.org/html/2505.06311v2) ([published version](https://aclanthology.org/2025.findings-emnlp.1060/)) | Fuse last-token hidden state with pooled self-attention gradients for a fixed response, then fit an MLP. Its cross-source Wiki/News and LaMini/BIPIA design motivates source-held-out checks and benign imperative examples. | Gradient extraction and a 400,000-dimensional gradient feature substantially change V4's forward-only compute contract. Published accuracy is not a low-FPR operating point; this is a later ablation, not a reason to enlarge the current small probe. |
| [LLMail-Inject, Abdelnabi et al.](https://arxiv.org/html/2506.09956) | A live adaptive email challenge gave attackers feedback across retrieval, detector, and tool-action objectives. The authors' analysis reports TaskTracker as one defense, and a 1,000-email Enron check found 4.0% and 5.7% FPR for two TaskTracker variants; flag-if-any stacking reached 10%. Use its task/query/attacker-email structure and adaptive attempts to stress a frozen V4 detector. | Those FPRs are specific to challenge thresholds and distribution. Repeated submissions are correlated; a raw row split leaks attack strategies and teams. Successful tool action, evasion, and injection presence are separate labels. |

**Proposed decision rule:** keep V4's existing fixed feature views as the baseline. Fit identical regularized linear probes with group-separated model selection, and test task-relative deltas only when the actual trusted task/pre-tool context is available. Freeze view, layer, weights, and threshold before a separately grouped final source; report frozen-threshold TPR/FPR, coverage, and agent utility. Treat any test-set ROC threshold as descriptive. The current V4 source labels remain development labels under the [solo policy](../FEATURE_V4_SOLO_REVIEW_PLAN.md); papers do not validate them.

## First-party dataset provenance and safe use

| Source | Verified origin and contents | Consequence for V4 |
| --- | --- | --- |
| [NVIDIA `Nemotron-RL-Agentic-Indirect-Prompt-Injection-v1` card](https://huggingface.co/datasets/nvidia/Nemotron-RL-Agentic-Indirect-Prompt-Injection-v1) | NVIDIA owns a 1,272-record, CC-BY-4.0, **fully synthetic, no-seed** RL dataset. Nemotron Super 3 generated tasks/environments and iteratively rewrote attacks against Nemotron Nano 3; only attacks whose target tool call succeeded were retained. Records carry a benign task, tool schemas, simulated environment, injection target, and deterministic trace verifier. | This is selected-for-success attack data, not a representative prevalence sample, a human-reviewed label source, or a clean-control set. Keep task/environment/injection lineage together; obtain genuinely independent benign examples for FPR. The verifier's action-success label does not automatically validate a document-level instruction-attempt label. |
| [Microsoft `llmail-inject-challenge` dataset card](https://huggingface.co/datasets/microsoft/llmail-inject-challenge), [analysis repository](https://github.com/microsoft/llmail-inject-challenge-analysis), [challenge code](https://github.com/microsoft/llmail-inject-challenge) | Microsoft publishes attacker-submitted email subjects/bodies from a closed public adaptive challenge in a simulated email assistant. The raw files have **370,724 phase-1** and **90,916 phase-2** submissions; separate unique-submission annotation files have **160,741** and **37,303** prompts, and `emails_for_fp_tests.jsonl` has **203** additional benign emails. Metadata includes team, scenario/level, objectives, and timing; annotation may be API output or an LLM judge. | Raw submissions are attacks attempted against disclosed defenses, not independent human ground-truth labels. Keep duplicates, same team, strategy, phase, and scenario/query families grouped; reconstruct the trusted query plus retrieved-email context when testing a task-conditioned probe. The 203 benign emails cannot establish a precise 1%-FPR tail on their own. |

The [LLMail paper's dataset appendix](https://arxiv.org/html/2506.09956) gives 461,640 raw submissions across phases, agreeing with the two repository file counts. Its 208,095 *unique prompts* count is different from the 198,044 annotated unique-submission entries listed by the current dataset card; do not silently equate those denominators. Phase 2 changed multiple defenses and input controls together, so a phase comparison does not isolate a probe effect. Neither source is an untouched test for a model or feature choice already developed on its records.

## Checks before a claim

1. Define the V4 label as an instruction attempt in lower-trust content relative to a specific authorized task. Keep it separate from defender compromise and from the papers' exposure label. Review disputed task-boundary cases; retain benign text that quotes or contains legitimate instructions.
2. Split by connected source/pair/attack lineage, not row. Deduplicate and separate source-provided, owner-reviewed, and accepted labels. Use one source only for development if it has already influenced feature choices.
3. Reserve clean calibration data after selecting the feature and a further final test. A zero-false-positive result on 203 independent benign items would still have a one-sided 95% upper FPR bound of about 1.47%; correlated emails make that bound optimistic. Report the achieved denominator and interval.
4. Evaluate clean task completion and attacker-objective success in agent episodes alongside detector counts. A latent exposure signal may be decodable while the agent still takes an unauthorized action, as the [agentic exposure paper](https://arxiv.org/html/2608.02657v2) explicitly demonstrates.
